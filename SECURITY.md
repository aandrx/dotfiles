# Reporting security and privacy problems

Do not open a public issue containing a credential, private configuration,
internal address, session transcript, or a content-bearing scanner report.

If GitHub private vulnerability reporting is enabled for this repository, use
its private reporting form. Otherwise ask the maintainer for a private channel
without sending the sensitive content. Do not assume private reporting is
configured merely because this file exists.

Report the affected path, line, rule/category, and commit ID. Avoid including
the value or a screenshot of it. A real exposed credential needs revocation or
rotation; removing a file from the latest commit is not sufficient.

See [PRIVACY.md](PRIVACY.md) for the disclosure response and publication gate.
